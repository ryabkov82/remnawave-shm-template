# Дополнительный трафик VFF — шаблон `remnawave_traffic_addon`

Шаблон выполняется только на `CREATE` услуги «Дополнительный трафик 300 ГБ». Он поднимает лимит уже существующего пользователя Remnawave `us_<parent_user_service_id>` до абсолютного итога из `user_services.settings` этой покупки.

Пользователя панели он не создаёт и не удаляет. Срок, расход, стратегию и параметры подключения не меняет. Пользовательский storage, подпись снимка, TTL-блокировку и собственную машину состояний шаблон не использует. Результат операции — код выхода задачи spool.

Основной шаблон в репозитории сохраняет оплаченный пакет при `ACTIVATE` и `PROLONGATE` VFF Standard. В Production он не установлен, поэтому продажу включать нельзя.

## 1. Откуда берутся данные покупки

Авторитетные источники — штатные сущности SHM:

- каталог `services`, услуга 17, категория `traffic-add-vff`;
- экземпляр `user_services`, в том числе после перехода в `REMOVED`;
- `user_services.settings`, записанные административным заказом;
- списание этого экземпляра;
- код выхода `CREATE` и `REMOVE`. Пока задача в `PROGRESS`, пакет ещё не считается завершённым. Срок экземпляра задаёт заказ через `end_date`. По его наступлении штатный `job_prolongate` запускает `REMOVE`.

Обязательные поля `settings`:

```json
{
  "purchase_id": "0123456789abcdef0123456789abcdef",
  "parent_user_service_id": 18432,
  "period": "2026-11",
  "period_starts_at": "2026-11-01T00:20:00Z",
  "period_ends_at": "2026-12-01T00:20:00Z",
  "base_limit_bytes": 322122547200,
  "addon_bytes": 322122547200,
  "applied_limit_bytes": 644245094400,
  "expected_amount": "150.00"
}
```

`purchase_id` — 32 шестнадцатеричных символа в нижнем регистре. Границы периода должны совпасть с `YYYY-MM-01T00:20:00Z` и тем же временем следующего месяца. Объёмы — положительные целые не больше 9007199254740991, и `applied_limit_bytes = base_limit_bytes + addon_bytes`. `expected_amount` — положительная сумма с не более чем двумя знаками после запятой, строка или число. Её записывает vpnbot из стоимости каталога в момент заказа. В шаблоне нет константы цены.

Эти числа фиксируются при заказе. Позднее изменение `traffic_addon.bytes` или цены в каталоге уже купленный пакет не переписывает: в PATCH уходит `applied_limit_bytes` экземпляра, а сумма сверяется с `expected_amount`.

Колонка `parent` не заполняется. Иначе услуга 17 становится ребёнком подписки и попадает в её события.

Списание подтверждено, когда у текущего экземпляра есть непустой `withdraw_date`, `user_service_id` этого экземпляра, тот же `user_id`, `service_id` 17, положительный `withdraw_id` и `total`, равный `expected_amount` с точностью до копейки. Неоплаченное списание — временный `payment_not_confirmed`. Чужое списание и другая сумма — постоянный `payment_mismatch`. Отдельного состояния оплаты шаблон не хранит. Деньги он не списывает и не возвращает.

## 2. Алгоритм

1. Событие не `CREATE`, услуга не 17 или категория не `traffic-add-vff` — постоянный отказ.
2. Проверить каталог модели `traffic_addon` и поля `settings`.
3. Сверить окно периода со свежим временем. `now >= period_ends_at` — постоянный `period_closed`. `now < period_starts_at` — временный `period_not_open`.
4. Проверить списание.
5. Прочитать родителя `GET /shm/v1/user/service?user_service_id=<parent>` сессией владельца. Чужой пользователь — `parent_not_owned`. `PROGRESS` — временный `parent_in_progress`: в SHM 3.7.0 `ACTIVATE` из `BLOCK` на время spool ставит этот статус и после успеха возвращает `ACTIVE`. `PROLONGATE` колонку статуса не меняет, услуга остаётся `ACTIVE`. `BLOCK`, `REMOVED` и любой другой статус, кроме `ACTIVE`, — постоянный `parent_not_active`. Чужая категория — `parent_category_mismatch`. Тариф вне `parent_service_ids` — `tariff_not_allowed`.
6. Прочитать `GET /api/users/by-username/us_<parent>`. Имя должно совпасть. Стратегия — `MONTH`. Статусы `ACTIVE` и `LIMITED` допустимы. `DISABLED` и `EXPIRED` дают `panel_status`; enable не вызывается. `expireAt` должен разбираться и быть в будущем.
7. Открыть период по правилу дат ниже. Сброс трафика шаблон не вызывает.
8. Непосредственно перед изменением ещё раз прочитать родителя, пользователя панели, срок и период.
9. Если лимит уже равен `applied_limit_bytes`, PATCH не отправляется и пакет повторно не увеличивается. Код 0 возвращается после этого чтения.
10. Если лимит не равен ни базе из `settings`, ни итогу — постоянный `limit_conflict`. Чужое значение не перезаписывается.
11. Если лимит равен базе, непосредственно перед запросом сохраняется UUID. PATCH содержит только этот `uuid` и `trafficLimitBytes`, равный `applied_limit_bytes`.
12. После PATCH пользователь читается снова. Код 0 возвращается только если лимит равен итогу, имя и стратегия сходятся, UUID совпадает с сохранённым перед PATCH, срок всё ещё в будущем и период ещё открыт. Другой UUID — постоянный `panel_uuid_mismatch`.
13. Если за время PATCH период закрылся, а лимит уже стал итоговым, код 0 не возвращается. В stderr пишутся `RESULT level=permanent reason=period_crossed`, наблюдаемый лимит и `period_ends_at`. Это диагностика для будущей сверки, не запись нового состояния.

Потеря ответа PATCH не добавляет пакет второй раз: повторное чтение видит итог и завершает `CREATE` без нового увеличения. Если панель лимит не сменила, выход временный и spool повторяет задачу.

Код 0 сопровождается `RESULT level=ok reason=applied`. Любой отказ — код 1 и `RESULT level=temporary|permanent reason=...` в stderr.

Временные ответы лежат в одном каталоге `mktemp -d` при `umask 077`. Обработчик `EXIT` удаляет его и при успехе, и при отказе. `curl` не использует `-k`. Скалярные значения SHM читаются через `toJson` и `jq`.

`TRAFFIC_ADDON_CLOCK_FILE` — тестовый шов. В Production переменная не задаётся.

## 3. Даты Remnawave 3.4.8

Период покупки открыт, когда текущее время внутри границ из `settings` и выполнено одно из условий:

- `lastTrafficResetAt` разобран, не позже текущего времени и не раньше `period_starts_at`;
- `lastTrafficResetAt` пуст, а `createdAt` разобран, не в будущем и не раньше `period_starts_at`.

Иначе временный `period_not_confirmed`. `createdAt` в будущем — временный `created_at_in_future`. Подписка, созданная в текущем периоде и ещё не прошедшая плановый сброс, пакет получает. Подписка прошлого периода без сброса в текущем окне, в том числе если панель была недоступна в `00:20` UTC, пакет не получает. Шаблон сброс не вызывает.

Плановый сброс `MONTH` обнуляет расход и пишет `lastTrafficResetAt`. Лимит он не меняет.

## 4. Контракт, который этим этапом не реализуется

### vpnbot

До заказа, под одним замком веб-заказа и Telegram в единственном процессе VFF:

- найти экземпляры услуги 17 этого пользователя, включая `REMOVED`;
- считать период занятым оплаченной строкой и строкой, которая ещё в `PROGRESS`;
- при неопределённом результате предыдущего заказа не создавать новый;
- передать в `settings` заказа неизменяемые условия: `purchase_id`, родителя, период, границы, три объёма и `expected_amount`, скопированный из стоимости каталога в этот момент;
- не передавать `months`, `cost` и колонку `parent`.

Потерянный ответ заказа восстанавливается повторным поиском того же `purchase_id` в `settings`.

### Основной шаблон

`ACTIVATE` и `PROLONGATE` подписки VFF Standard (категория `vpn-mz-test`, услуги 3–6, стратегия `MONTH`) читают экземпляры услуги 17 и их списания объектами SHM. Template Toolkit 2.27 не выполняет ложную ветку `IF`, поэтому остальные события и категории эти списки не запрашивают. Spool разбирает шаблон в SSH-транспорте непосредственно перед командой, а не при постановке задачи. На сервер Remnawave уходит уже выбранное число, без административного токена SHM. Текущий каталог услуги 17 шаблон не читает: для уже оплаченного пакета действуют settings экземпляра.

- Оплаченный `ACTIVE`, `REMOVED` или `PROGRESS` текущего периода записывает `applied_limit_bytes` из settings экземпляра, если текущий лимит панели равен сохранённой базе или этому итогу.
- Если лимит панели отличается от обеих величин, в том числе когда он равен 0, пакет его не перезаписывает.
- `PROGRESS` поэтому не затирает итог, если PATCH уже прошёл и ответ потерялся, и ставит тот же итог, если лимит всё ещё равен базе.
- Пакет другого периода не переносится после подтверждённого сброса. Если граница уже прошла, а `lastTrafficResetAt` ещё не подтвердил новый период, итог сохраняется.
- Подписка без пакета получает каталожный лимит, включая замену ручного лимита и 0.
- Неоплаченный пакет, пакет другой подписки, Friends Connect и Premium не меняют штатный лимит.
- Пустой ответ `toJson` — это пустая история. Нечитаемая история и JSON `null` не подменяют текущий лимит панели, включая 0. Если этот лимит прочитать нельзя, задача завершается с кодом 1 и spool повторяет её.

`CREATE` новой основной подписки по-прежнему записывает каталожный лимит. Сброс использованного трафика не изменён. Шаблон в Production этим этапом не устанавливается.

### Завершение пакета

Отдельной сверки vpnbot нет. `REMOVE` того же шаблона:

- проверяет, что покупка и оплаченное списание принадлежат этой подписке;
- ждёт конца расчётного периода и `lastTrafficResetAt` не раньше этого конца и не позже текущего времени;
- не снижает лимит, если у родителя есть другой оплаченный пакет ещё не закончившегося периода, включая оплаченный `PROGRESS`;
- возвращает сохранённую базу только когда текущий лимит равен сохранённому итогу;
- завершается без записи, если лимит уже равен базе или имеет другое число, включая 0;
- не требует от родителя статуса `ACTIVE` и будущего `expireAt`;
- при окончательно удалённой подписке и ответе 404 панели завершается без `PATCH`;
- при недоступной панели, нечитаемой истории или неподтверждённом сбросе выходит с кодом 1, и spool повторяет задачу.

`PATCH` меняет только `trafficLimitBytes` указанного UUID. `reset-traffic`, срок, статус и параметры подключения не вызываются.

Дополнительное хранилище и отдельный протокол блокировок не вводятся: у текущей установки `WORKERS_COUNT=1`, а повторный заказ закрывается замком одного процесса vpnbot. База сама не запретит второй заказ услуги 17, если он обойдёт этот процесс.

## 5. Блокирующие условия Production

1. Изменение основного шаблона есть в репозитории, но в Production шаблон не установлен: действующий `ACTIVATE` и `PROLONGATE` по-прежнему записывают каталожный лимит.
2. Код 1 у `REMOVE` повторяется spool, пока задача не получит pause.
3. Сброс трафика сам лимит не возвращает. Лимит возвращает `REMOVE` после подтверждённого сброса.
4. Событие `CREATE` нельзя вешать на группу серверов 6 без `template_id`: SSH иначе запустит шаблон `remnawave` и создаст пользователя `us_<id дополнительной услуги>`.
5. Второй заказ услуги 17 мимо единственного процесса vpnbot VFF база не отклонит.

Отдельно остаётся ограничение ядра: два одновременных `is_pay` могут увести баланс в минус.

## 6. Развёртывание, которое этим этапом не выполняется

1. Добавить в SHM шаблон с идентификатором `remnawave_traffic_addon` и содержимым `templates/shm-remnawave-traffic-addon.template.sh`.
2. Не создавать событие и не заказывать услугу 17, пока не закрыты блокирующие условия и vpnbot не пишет `settings`.
3. Не привязывать категорию `traffic-add-vff` к группе 6 без `template_id`.
4. Этим этапом события не регистрируются. Позже для `REMOVE` нужен `template_id` шаблона `remnawave_traffic_addon`: без него SHM либо только сменит статус, либо запустит основной шаблон. `ACTIVATE`, `BLOCK`, `PROLONGATE` и `CHANGED` для категории пакета не добавлять.

Черновик события, которое сейчас создавать нельзя:

```json
{
  "kind": "UserService",
  "name": "create",
  "title": "vff traffic addon",
  "server_gid": 6,
  "settings": {
    "category": "traffic-add-vff",
    "template_id": "remnawave_traffic_addon"
  }
}
```

Группа 6 даёт адрес и токен Remnawave через `server.settings.remnawave.api` и `server.settings.remnawave.token`. Токен в лог не пишется.

## 7. Тесты

`python3 -m unittest tests.test_template_traffic_addon -v`

Локальный HTTP mock. Покрыты выдача абсолютного лимита, повтор без второго увеличения, неоплаченное, чужое и несовпавшее по сумме списание, чужая подписка и тариф, временный `PROGRESS` родителя, `BLOCK` и `REMOVED`, `DISABLED` и `EXPIRED`, `LIMITED` без enable, закрытый и неподтверждённый период, новая подписка без `lastTrafficResetAt`, ручной лимит, потеря ответа PATCH, смена UUID между PATCH и подтверждающим GET, обрыв до применения, потеря подтверждающего GET, граница периода до и во время PATCH, прошедший `expireAt`, штатное продление, очистка временных файлов и неисполнение shell-подстановки.
